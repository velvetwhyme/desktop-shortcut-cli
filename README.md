# desktop-shortcut-cli

`desklink` — небольшая CLI-утилита на Rust для создания, просмотра и удаления
`.desktop`-ярлыков в `~/.local/share/applications/`.

Проект рассчитан в первую очередь на Arch Linux, но работает на любом Linux:
использует XDG-каталоги и POSIX-права на выполнение. Root не требуется —
утилита пишет только в каталог ярлыков текущего пользователя.

Команда называется `desklink`, Arch-пакет — `desktop-shortcut-cli`.

## Возможности

- Создание ярлыков для Linux-бинарников, shell-скриптов и Windows `.exe`.
- Абсолютные и относительные пути, поиск команд через `PATH`.
- Проверка существования файлов и каталогов; права на выполнение для Linux-файлов.
- Корректное экранирование пробелов и специальных символов в `Exec`.
- Автоматический запуск `.exe` через `wine` или `wine64`, если они есть в `PATH`.
- Явная команда запуска для `.exe`: `umu-run`, `proton`, другой launcher или свой `wine`.
- Интерактивный запрос недостающих `--name` и `--path`.
- Список только тех ярлыков, которые создала эта утилита.
- Удаление ярлыков по отображаемому имени, имени файла или полному пути.
- Защита от случайной перезаписи: вопрос в терминале или ошибка без TTY.
- Чужие `.desktop`-файлы не удаляются и не перезаписываются даже с `--force`.
- Один бинарник без сторонних crate-зависимостей.

## Поддерживаемые сценарии

- Локальный Linux-бинарник или скрипт с относительным либо абсолютным путём.
- Команда, установленная в `PATH` (`htop`, `code`, `firefox` и т.п.).
- Приложение, которому нужна рабочая директория и аргументы запуска.
- Консольная программа, которую нужно открыть в терминале.
- Windows-игра или программа через Wine.
- `.exe` через альтернативный launcher, если автоматический Wine не подходит.
- Пути и названия с пробелами, кавычками, `$`, `%` и кириллицей.
- Просмотр и удаление только собственных ярлыков без риска задеть системные.

## Требования

- Linux.
- Для сборки: Rust 1.85 или новее (edition 2024) и Cargo.
- Для автоматического запуска `.exe`: `wine` или `wine64` в `PATH`.
- Для сборки Arch-пакета: `base-devel` и `makepkg` (входит в пакет `pacman`).

## Установка

### Готовый Arch-пакет

Готовые пакеты публикуются в разделе GitHub Releases. После публикации релиза
скачайте `desktop-shortcut-cli-0.1.0-1-x86_64.pkg.tar.zst` и установите:

```bash
sudo pacman -U ./desktop-shortcut-cli-0.1.0-1-x86_64.pkg.tar.zst
```

Пакет устанавливает:

```text
/usr/bin/desklink
/usr/share/doc/desktop-shortcut-cli/README.md
/usr/share/doc/desktop-shortcut-cli/LICENSE
```

Удаление пакета не затрагивает ярлыки, созданные пользователем:

```bash
sudo pacman -R desktop-shortcut-cli
```

### Сборка из исходников

```bash
cargo build --release --locked
./target/release/desklink --help
```

Проверка:

```bash
cargo test --locked
```

### Сборка Arch-пакета

PKGBUILD находится в `packaging/`. Каталог `packaging/` используется потому,
что `makepkg` создаёт собственный `src/`, а в корне Cargo-проекта уже есть
каталог `src/` с исходным кодом.

```bash
cd packaging
./update-source.sh   # пересобрать source-архив и sha256sums
makepkg
```

Если Rust установлен через rustup, а пакета `rust` в pacman нет:

```bash
PATH="$HOME/.cargo/bin:$PATH" makepkg --nodeps
```

Сейчас `source` в `PKGBUILD` указывает на локальный архив, который создаёт
`update-source.sh`. Перед публикацией в AUR его нужно заменить на URL
GitHub-релиза и обновить `sha256sums` и `.SRCINFO`.

## Использование

```text
desklink [ПАРАМЕТРЫ]
```

| Параметр | Описание |
|---|---|
| `-n, --name <НАЗВАНИЕ>` | Отображаемое название ярлыка |
| `-p, --path <ПУТЬ>` | Путь к исполняемому файлу или команда запуска |
| `-i, --icon <ПУТЬ>` | Путь к файлу иконки |
| `-w, --workdir <ПУТЬ>` | Рабочая директория приложения |
| `-a, --args <АРГУМЕНТЫ>` | Аргументы запуска (можно указывать в кавычках) |
| `-t, --terminal` | Запускать приложение в терминале |
| `--list` | Показать ярлыки, созданные `desklink` |
| `--remove <НАЗВАНИЕ>` | Удалить ярлык, созданный `desklink` |
| `--force` | Перезаписать ярлык `desklink` без вопроса |
| `-V, --version` | Показать версию |
| `-h, --help` | Показать справку |

Короткие флаги нельзя объединять: вместо `-np` нужно писать
`-n "Имя" -p /путь`. Длинные параметры можно указывать и через `=`,
например `--name="Test App"`.

### Примеры

Создать ярлык для локального исполняемого файла:

```bash
desklink -n "Test App" -p ./app
```

С иконкой:

```bash
desklink -n "Test App" -p ./app -i ./icon.png
```

Linux-бинарник с рабочей директорией и аргументами:

```bash
desklink -n "Редактор" -p /usr/bin/code -w ~/Projects -a "--new-window"
```

Shell-скрипт в терминале:

```bash
desklink -n "Скрипт" -p ./backup.sh -t
```

Команда, найденная через `PATH`:

```bash
desklink -n "Монитор" -p htop -t
```

Перезаписать существующий ярлык без вопроса:

```bash
desklink -n "Test App" -p ./new-app --force
```

### Интерактивное создание

Если запустить `desklink` в терминале без `-n` и `-p`, программа запросит
недостающие значения:

```text
$ desklink
Название ярлыка: Test App
Путь к исполняемому файлу или команда: ./app
Ярлык создан: /home/user/.local/share/applications/test-app.desktop
```

Без аргументов вне терминала печатается справка. Если не хватает только
одного обязательного параметра, запрашивается только он.

### Просмотр и удаление ярлыков

```bash
desklink --list
```

Удаление по отображаемому имени:

```bash
desklink --remove "Test App"
```

Удаление по имени файла или полному пути:

```bash
desklink --remove test-app.desktop
desklink --remove ~/.local/share/applications/test-app.desktop
```

`--list` и `--remove` работают только с ярлыками, созданными этой утилитой
или её предшественником `label-cli`. Чужие `.desktop`-файлы не изменяются.

### Wine и `.exe`

Если `-p` указывает на существующий файл с расширением `.exe`
(регистр расширения не важен), `desklink` ищет `wine`, затем `wine64` в `PATH`
и добавляет найденный launcher в `Exec`. Путь к `.exe` при этом записывается
абсолютным.

```bash
desklink -n "Game" -p ./game.exe -w ./game-data
```

Если Wine не установлен, программа завершится с ошибкой и предложит явную
команду запуска. Альтернативный launcher указывается прямо в `-p`:

```bash
desklink -n "Game" -p "umu-run ./game.exe" -w ./game-data
desklink -n "Game" -p "wine /path/to/game.exe"
```

Относительные пути к существующим `.exe` в явной команде также приводятся
к абсолютным, поэтому не зависят от значения `Path=` в ярлыке.

Аргументы из `-a` разбираются как shell-подобная строка: поддерживаются
одинарные и двойные кавычки и экранирование через `\`.

## Что создаётся

Файл `~/.local/share/applications/<slug>.desktop`, например:

```ini
[Desktop Entry]
Type=Application
Version=1.5
Name=Test App
Exec="/home/user/games/Test App/game.exe"
Comment=Shortcut created by desklink
Icon=/home/user/games/Test App/icon.png
Path=/home/user/games/Test App
Terminal=false
Categories=Utility;
X-Label-CLI=true
```

Имя файла получается из названия: Unicode-буквы, цифры и `_` сохраняются,
остальные символы схлопываются в один дефис, длина ограничена 80 символами.
Если после преобразования имя пустое, используется `shortcut`.

Иконка не копируется: в ярлык записывается абсолютный путь к ней. Если
переместить или удалить иконку, её нужно указать заново.

## Безопасность и совместимость

### Защита файлов

- Утилита не требует root и не пишет за пределы каталога ярлыков
  (`$XDG_DATA_HOME/applications` или `~/.local/share/applications`).
- `--list` и `--remove` учитывают только файлы с маркером `X-Label-CLI=true`.
- `--force` перезаписывает только обычный файл, созданный этой утилитой.
- Симлинки, каталоги и чужие `.desktop`-файлы не перезаписываются даже
  с `--force`.
- Запись выполняется атомарно: сначала временный файл, затем `rename`.
- Названия с управляющими символами отклоняются.
- Сетевые запросы не выполняются.

### Совместимость с `label-cli`

Маркер `X-Label-CLI=true` намеренно сохранён без изменений. Ярлыки, созданные
старой версией `label-cli`, по-прежнему:

- отображаются через `--list`;
- обновляются через `--force`;
- удаляются через `--remove`.

При обновлении значение `Comment=` заменяется на новое, но принадлежность
определяется только по маркеру. Новый пакет устанавливает только
`/usr/bin/desklink` и не конфликтует со старым пакетом `label-cli`, поэтому
на время миграции обе команды могут быть установлены одновременно.

## Архитектура

```text
src/main.rs       точка входа и сценарии команд
src/cli.rs        разбор аргументов, справка, интерактивный режим
src/exec.rs       разбор команды, PATH, проверка путей, выбор Wine
src/desktop.rs    генерация Desktop Entry и экранирование
src/shortcut.rs   создание, список, удаление и проверка принадлежности
src/error.rs      типы ошибок и коды возврата
tests/cli.rs      интеграционные тесты собранного бинарника
packaging/
  PKGBUILD          сборочный файл Arch Linux
  update-source.sh  пересборка source-архива и контрольной суммы
  .SRCINFO          метаданные для AUR
```

Порядок работы при создании ярлыка:

1. `cli` разбирает аргументы и при необходимости запрашивает недостающие.
2. `exec` проверяет путь или команду, ищет её в `PATH`, добавляет Wine для
   `.exe` и нормализует аргументы.
3. `desktop` формирует Desktop Entry и экранирует значения.
4. `shortcut` проверяет существующий файл и атомарно записывает ярлык.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Ошибка файла, пути, записи или удаления |
| `2` | Неверные аргументы командной строки |

## Ограничения

- Утилита рассчитана на Linux: используются POSIX-права на выполнение.
- Для `.exe` без явной команды нужен `wine` или `wine64` в `PATH`.
- Field codes вида `%f`/`%u` не подставляются: `%` экранируется как литерал.
- Иконки по имени темы не поддерживаются — только путь к файлу.
- Локализованные ключи `Name[xx]` не создаются: записывается один `Name`.
- Категория всегда `Utility;`, изменить её через CLI нельзя.
- Ярлыки не добавляются в системное меню принудительно: среда рабочего стола
  подхватывает их из каталога приложений сама. Обновление меню зависит от DE.
